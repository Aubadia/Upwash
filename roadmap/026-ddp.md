# 026 — Data-Parallel Training (DDP)

## Behavior

Train one model on W processes (ranks), one per GPU, launched by `torchrun`. Each rank
reads a different equally sized local batch B, DDP averages the gradients during
backward, and every rank applies the same update. W ranks of batch B must therefore
train like one process with batch W·B.

This is the first optimization moved from the `experiment` branch to `main` by hand,
before the next lab (data curation, Paloma BPB). The `experiment` implementation is
the behavioral reference, not code to copy:

- `2229544` — `RankShard` and sample-level shuffling.
- `7598e33` — gradient clipping, per-group LR logging, global token counts.
- `975882b` — `torchrun` DDP entry point and the 2-rank CPU equivalence test.

Only DDP itself moves in this task. `Permute` (shuffling), gradient clipping,
`torch.compile`, FlashAttention-3 and checkpointing move as separate tasks.

Branch `feat/ddp`, from `origin/main` at `1faf6dc`.

## Agreed Interface — Steps 1 and 2 (2026-11-19)

```python
from upwash.core.data import RankShard

shard = RankShard(dataset, rank=r, world_size=W, batch_size=B)
len(shard)   # len(dataset) // W
shard[i]     # batch, offset = divmod(i, B) -> dataset[batch * W * B + r * B + offset]

Trainer(..., world_size=1)        # positive int; token metrics are multiplied by it
build_trainer(..., world_size=1)  # forwarded to Trainer
```

- Global batch g is samples `[g·W·B, (g+1)·W·B)`; rank r takes the r-th block of B.
  Blocks, not `rank::W` striding, so which samples global step g reads depends on W·B
  only. This keeps resume and 1-vs-8-GPU comparisons simple.
- A dataset that does not fill whole global batches is rejected with `ValueError`.
  Otherwise one rank would run an extra update and the others would wait forever in
  its all-reduce.
- Non-positive `world_size` or `batch_size` raises `ValueError` naming that argument. Both are checked before the rank and before the divisibility check, so `world_size=0` is not misreported as a bad rank and `batch_size=0` never divides by zero (added 2026-11-19).
- An invalid rank (negative or `>= world_size`) raises `ValueError`. Negative indices
  work; out-of-range indices raise `IndexError`.
- `train/total_tokens_seen` and `train/tokens_per_second` become global: local count
  (after padding exclusion) times `world_size`. The lab score `oj_total_tokens` is a
  global count. `world_size` is bookkeeping only: it must not scale the loss, the
  gradients or the update, because DDP has already averaged them.
- `world_size` must be a positive integer (`ValueError` otherwise).

## Agreed Interface — Step 3 (2026-11-19)

`Runtime` lives in `src/upwash/core/runtime.py`. It was first agreed as `core/distributed.py` and renamed the same day: most users (device placement, rank-0 logging, export, checkpointing) only ask "which device, am I the main process", which also applies to one process. Collective helpers (barrier, all-reduce) may later get their own `core/distributed.py`. (Decision 1: public core
infrastructure, because checkpointing, distributed evaluation and rank-0 logging will
need it; not private to `train.py` as on `experiment`).

```python
from upwash.core.runtime import Runtime, setup_runtime, teardown_runtime

@dataclass
class Runtime:
    rank: int = 0
    world_size: int = 1
    device: str = "cpu"
    initialized_here: bool = False   # teardown destroys the group only if True
    @property
    def is_main(self) -> bool: ...    # rank == 0

runtime = setup_runtime(device)       # device: the configured "cpu", "cuda" or "cuda:N"
teardown_runtime(runtime)
```

- Read `WORLD_SIZE`, `RANK`, `LOCAL_RANK` (set by `torchrun`). If `WORLD_SIZE` is
  missing or 1, return `Runtime(0, 1, device, False)` unchanged and call nothing.
- `LOCAL_RANK` defaults to `RANK` when missing.
- If a process group already exists (`dist.is_initialized()`), join it: initialize
  nothing, `initialized_here=False`.
- CPU device: `dist.init_process_group(backend="gloo")`; the device stays `"cpu"`.
- CUDA device (`"cuda"` or `"cuda:N"`): first `torch.cuda.set_device(local_rank)`, then
  `dist.init_process_group(backend="nccl")`. The device becomes `cuda:{local_rank}`,
  and a configured index is replaced. On a second node, global rank 9 is GPU 1. Without
  `set_device` first, NCCL may put every rank's communicator on GPU 0.
- `teardown_runtime` calls `dist.destroy_process_group()` only when
  `initialized_here` is True.
- Call these through the module objects (`torch.distributed`, `torch.cuda`), not
  `from torch.distributed import init_process_group`. The unit tests replace the
  module attributes with recording fakes.

## Agreed Behavior — Step 4 (2026-11-19)

`train(config)` in `src/upwash/train.py` (main has no export yet, so there is none to wire):

1. `runtime = setup_runtime(config.device)`, then `torch.manual_seed(config.seed)`. The
   same seed gives every rank the same initial weights, and DDP also broadcasts rank 0's.
2. When `world_size > 1`, wrap the training dataset in `RankShard(..., rank, world_size,
   batch_size=config.batch_size)` before the `DataLoader`. The evaluation data is not
   sharded; every rank evaluates the full set.
3. Build the model on `runtime.device`. When `world_size > 1`, wrap it in
   `torch.nn.parallel.DistributedDataParallel(model, device_ids=[cuda index] or None on
   CPU, forward_sync_buffers=False)`. The Trainer trains the wrapper.
4. Pass `world_size=runtime.world_size` to `build_trainer`. `total_steps` is the
   per-rank `len(train_loader)`.
5. Create the `FlockLogger` only when `runtime.is_main`.
6. Return the unwrapped model in `TrainResult`, so no parameter gets a `module.` prefix.
7. When `world_size > 1`, every rank calls `dist.barrier()` after training. Every rank
   calls `teardown_runtime(runtime)` in `finally`, also when training fails.

Reviewed before writing tests:

- Several ranks need whole global batches. One process still accepts a final partial
  batch (existing test: 5 sequences, batch 2 gives `[2, 2, 1]`); several ranks reject
  it through `RankShard`, because one rank would otherwise run an extra update.
- When one rank fails, the others may block in a collective. `torchrun` terminates the
  whole group when a worker exits non-zero; `train()` only has to surface the error
  and tear down.
- With padding, ranks could average different numbers of valid tokens, so DDP's mean of
  per-rank means would not equal the global mean. Packed data has no padding; this is
  recorded as a limit.
- Keeping the DDP wrap in `train.py` follows the current composition, where `train.py`
  already builds the loaders and the model. Moving composition into the builder is a
  separate refactor.
- Gradient clipping moves later (decision 2, 2026-11-19). Until then:
  1. The two-rank test runs without `max_grad_norm`. When clipping moves, add it back
     to that test. Clipping after backward sees the all-reduced gradients, so every rank
     should compute the same norm; the test must confirm this.
  2. Do not run real experiments from `main`. Every `experiment` run used
     `max_grad_norm=1.0`, and clipping must be on `main` before the next lab's training.

Known limits, deferred:

- Logged `train/loss` is rank 0's local mean, not the global mean.
- Every rank evaluates the full dev set.

## Tests

`tests/unit/core/test_rank_shard.py` (CPU):

- 12 samples, W 2, B 3: rank 0 gets `[0,1,2,6,7,8]`, rank 1 gets `[3,4,5,9,10,11]`.
- W 4, B 2, 24 samples: equal lengths, and every sample is covered exactly once.
- For every step, joining the ranks' `DataLoader` batches in rank order equals the
  single-process `DataLoader` batch of size W·B. This is the property DDP equivalence
  relies on.
- W 1 is the dataset itself. A partial global batch is rejected, as are ranks −1 and 2,
  `world_size` 0 and −1 (message names the world size) and `batch_size` 0 and −3.
  Negative and out-of-range indices are checked.

`tests/unit/core/test_trainer_world_size.py` (CPU, `nn.Embedding` + SGD):

- With W 4, `train/total_tokens_seen` is 4× the local count, with and without padding
  exclusion, and stays an `int`.
- With W 4, `train/tokens_per_second` is 4× the local rate. This uses a simulated
  clock: 3 s per update.
- Omitting `world_size` equals `world_size=1`.
- W 4 and W 1 give bit-identical weights and identical logged losses.
- `world_size` 0 and −2 are rejected.
- `build_trainer(world_size=8)` forwards to the Trainer: 4 tokens are reported as 32.

`tests/unit/core/test_runtime.py` (CPU; `init_process_group`, `is_initialized`,
`destroy_process_group` and `cuda.set_device` replaced by recording fakes):

- Without torchrun variables (device `cpu`, `cuda`, `cuda:3`), and with `WORLD_SIZE=1`:
  single-process `Runtime`, `is_main`, and no calls.
- CPU, W 4, rank 2: `Runtime(2, 4, "cpu", True)`, not main, one `init` with `gloo`.
- CUDA, W 16, rank 9, local rank 1: device `cuda:1`; calls exactly
  `[set_device(1), init("nccl")]`, in that order.
- A configured `cuda:0` becomes `cuda:{local_rank}`. A missing `LOCAL_RANK` defaults to
  `RANK`.
- An existing group is joined, not re-initialized (`initialized_here=False`, no calls).
- Teardown destroys only a group with `initialized_here=True`. `Runtime()` defaults
  describe one CPU process.

`tests/integration/test_runtime_process_group.py` (two spawned CPU processes, real gloo):

- Each joins through `setup_runtime("cpu")` and gets its rank, world size 2, device
  `cpu` and `is_main` only on rank 0.
- An `all_reduce` of rank + 1 gives 3 on both ranks.
- After `teardown_runtime`, the group is gone.

`tests/unit/test_train_ddp.py` (one process; fake `Runtime` for rank 0 or 1 of 2,
recording `DistributedDataParallel`, `dist.barrier` and `teardown_runtime`, TinyLM with
distinct token ids):

- One process: no DDP, no barrier, all 8 samples, 4 updates, the built model returned.
- Rank 1 of 2:
  - 2 updates on exactly samples (2, 3) and (6, 7).
  - One DDP wrap of the built model, with `device_ids` None and
    `forward_sync_buffers=False`.
  - The unwrapped model is returned; the barrier is reached; teardown comes last.
- Only rank 0 creates the Flock run (rank 0: 1 run, rank 1: 0 runs).
- When the trainer build fails on rank 1, the original error propagates and teardown
  still runs.
- On several ranks, 6 sequences (not whole global batches of 4) raise `ValueError`.

`tests/integration/test_ddp_training.py` (two spawned gloo ranks, real tiny Llama, Muon +
AdamW, WSD, no clipping):

- Each rank (batch 2) runs 4 updates, like one process with batch 4.
- Replicas are bit-identical and match the single process within atol 5e-4.
- Every parameter moved by more than 10x the tolerance.
- No parameter has a `module.` prefix, and the group is torn down.
- Tolerance source, measured 2026-11-19 with a scratch composition of main's components:
  replicas identical, a largest difference of 1.3e-4 (a Muon matrix; bf16
  orthogonalization), AdamW about 1e-6, and a smallest movement of 3.4e-2.
